\opening{Dear Editors,}

Please consider the enclosed manuscript, ``Bounded-memory streaming redaction of personal data and credentials with a whole-document equivalence guarantee,'' for publication in \emph{Computers \& Security}.

Tools that remove personal data and credentials from logs and exports are widely deployed, but the artefacts they process are routinely larger than memory, so they must be processed in chunks. We could find no system in the redaction, de-identification or secret-scanning literature that states any relationship between its chunked output and its whole-document output. The gap matters operationally: a value straddling a chunk boundary can be written out in the clear, and nothing in the output signals that it happened.

The paper closes that gap. Given bounds on span length and context that each detector declares and that regression tests enforce, we prove the streamed output equals the whole-document output, the parallel output equals the sequential output byte for byte, and working memory is independent of input size. We then measure what this costs and what it buys, on held-out test splits against Microsoft Presidio in three configurations and against gitleaks and TruffleHog, with bootstrap confidence intervals, a component ablation, and a memory scaling curve from 8\,MiB to 2\,GiB.

We have tried to report the evaluation as a referee would want to see it. Where we lose, we say so: free-text recall without a named-entity model is low, and against Presidio's larger model our entity coverage is not significantly better. One corpus was inspected during rule development, and rather than drop it we report pre-exposure and post-exposure results side by side and bound the contamination. All code, split manifests, the evaluation harness and the raw results underlying every number are public.
