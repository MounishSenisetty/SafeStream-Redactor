### B. Consolidated, obsolete or superseded documentation
* **Stale artifact:** the tracked paper PDF no longer matches its `.tex`.
* **Zero inbound links, overlapping content:** `docs/SYSTEM_ARCHITECTURE_AND_CODEBASE.md`
  (1,194 lines, written for 0.4.0, so it predates `operators.py`, `detectors/regional.py`

  yet", but the fanotify daemon shipped (`watch.py`, `docs/FANOTIFY.md`). The eBPF design
  content is still valuable, so the fix is to update the banner and keep the file.
* **Historical snapshots:** `docs/PERF_ASSESSMENT.md` (a "Phase 1" assessment of "~4.8 K LOC
  ... 30 test modules"; the repo is now 11.7 K LOC and 54 modules) and `docs/ROADMAP.md` (a
  plan derived from the v0.1.0 `AUDIT.md`, many of whose items are closed).
* **A report that corrects itself:** `benchmarks/redactionbench/AUDIT.md` opens with
  *"CORRECTION (see VALIDATION.md)"*, retracting its "0.431 all-gold RChar ceiling".
* **Possible duplication:** `SEMANTIC_DETECTION.md` and `SEMANTIC_ENSEMBLE.md` (referenced
  only by each other and by two scripts); `docs/architecture/plantuml/*.puml` re-draws five
  models that already exist as Mermaid (the directory README says a second notation is kept
  "where it adds value").

### C. Stale tests and unused fixtures
* `tests/test_memstream_wal.py` is a spec for a module (`memstream/wal.py`) that does not exist.
  It is skipped on every run by `importorskip` ("written in a later step").
* `tests/test_memstream_events.py` tests only the unfinished `memstream` package.
* No orphaned scratch scripts, no superseded fixtures, no generated test output are tracked.
  (`vulture` reports unused variables in `tests/`; they are pytest fixtures requested by name.)

### D. Dead stubs and unreferenced files
* `memstream/producers/__init__.py`: one docstring promising "built-in and example event
  producers"; none exist and nothing imports it.
* `memstream/` itself: declares itself "UNFINISHED, NOT DISTRIBUTED"; nothing in the
  redaction path imports it; it is excluded from the wheel and sdist.
* `native/examples/{dump_classes,per_pattern,profile_digits}.rs`: developer profiling tools,
  referenced only by the codebase reference doc.

## 6. Post-Cleanup Verification Steps

Run from the repository root, ideally in a fresh virtual environment so nothing stale is cached.

```bash
# 0. Fresh environment with the project's dev extras
python -m venv /tmp/prune-check && . /tmp/prune-check/bin/activate
pip install -e '.[dev]'

# 1. Lint, formatting and strict type checking (all must print "passed" / "Success")
ruff check .
ruff format --check .
mypy

# 2. Full test suite with the 95% coverage gate
python -m pytest -q --cov=safestream_redactor

# 3. The docs-consistency guard (it scans the docs you may have removed)
python -m pytest -q tests/test_docs_consistency.py

# 4. No dangling references to anything you deleted (replace the pattern with what you removed)
git grep -nE "memstream|PERF_ASSESSMENT|ROADMAP\.md|SYSTEM_ARCHITECTURE_AND_CODEBASE|PROJECT_SPLITS|\.pdf" -- . ':!REDUNDANT_FILES_AUDIT.md'

# 5. Packaging and deployment files still parse
python -m build --wheel --sdist 2>/dev/null || pip wheel --no-deps -w /tmp/wheel-check .
docker compose -f docker-compose.yml config -q && echo "compose: valid"
(cd native && cargo test --locked)          # optional, only if you removed or touched native/

# 6. Working tree contains exactly your intended changes
git status --short
git diff --stat HEAD
```
