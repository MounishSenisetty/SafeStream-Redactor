# SafeStream-Redactor vs Microsoft Presidio — like-for-like

> **Not reproduced (2026-10-03).** The figures below come from an earlier harness and
> environment and were not reproduced by the Phase 0 baseline (`benchmarks/harness.py`,
> isolated per-tool virtualenvs, one thread per tool, dev splits). Treat them as
> historical. Current measured numbers: the README's Evaluation section and
> [`research/reports/gap-report.md`](../research/reports/gap-report.md).

Generated by `benchmarks/presidio_compare.py`; raw numbers in
[`research/results/raw/presidio_compare_2026-10-02.json`](../research/results/raw/presidio_compare_2026-10-02.json).

**Environment.** Python 3.11, Linux 6.18 x86_64, 4 vCPU shared container, one run per
cell (no repeats, no confidence intervals on throughput). SafeStream-Redactor 0.4.0 with
the native core built from `native/` (`maturin develop --release`); `presidio-analyzer`
2.2.364; spaCy 3.8.16 with `en_core_web_sm` and `en_core_web_lg` 3.8.0. Each tool runs
in its own process. Entity recall counts a gold span only when **every** character of
it is redacted; character precision/recall are over the union of gold characters.
"Tool RSS" is peak RSS minus what the process held after loading the dataset.

## How to read this: compare within a tier, never across

An earlier version of this page reported SafeStream's native regex core as
"250–450× faster than Presidio". That number is **reproducible but not like-for-like**:
the Presidio row was the full default `AnalyzerEngine()`, which loads a large spaCy
model and runs NER on every document, so it measured *regex vs regex-plus-NLP*. The
tiers below separate the two.

| Tier | SafeStream | Presidio | What is being compared |
| --- | --- | --- | --- |
| **Pattern** (no ML on either side) | `safestream-native`, `safestream-python` | `presidio-regex` — Presidio's own pattern/checksum recognizers called directly, **no NLP engine** | rule-based detection only |
| **NER** (same spaCy model) | `safestream-native-ner` (`en_core_web_sm`) | `presidio-sm` — full `AnalyzerEngine` on `en_core_web_sm` | rules + the same small NER model |
| **Reference** | — | `presidio` — defaults (`en_core_web_lg`) | Presidio as most users run it |

## Like-for-like speed and memory (from the raw JSON)

| Tier | Dataset | SafeStream vs Presidio throughput | Tool memory (SafeStream / Presidio) |
| --- | --- | --- | --- |
| Pattern, native core vs `presidio-regex` | logs | **147×** | 29 MB / 103 MB |
| Pattern, native core vs `presidio-regex` | RedactionBench | **42×** | 25 MB / 67 MB |
| Pattern, pure Python vs `presidio-regex` | logs | **33×** | 7 MB / 103 MB |
| Pattern, pure Python vs `presidio-regex` | RedactionBench | **15×** | 9 MB / 67 MB |
| NER, `safestream-native-ner` vs `presidio-sm` | logs | **1.7×** | 603 MB / 248 MB |
| NER, `safestream-native-ner` vs `presidio-sm` | RedactionBench | **2.0×** | 644 MB / 237 MB |
| *Not like-for-like:* native core vs full `presidio` (lg) | logs / RedactionBench | *543× / 281×* | *29 MB / 842 MB* |

The honest headline is therefore **15–147× in the pattern tier and about 2× in the NER
tier**, not 250–450×. In the NER tier SafeStream is **not** smaller: its NER path uses
roughly 2.5× *more* memory than Presidio on the same model, so the memory advantage
exists only without ML.

## Pareto view (RedactionBench, prose; higher is better except memory)

| Configuration | Throughput | Char precision | Char recall | Entity recall | Tool memory | Memory bound |
| --- | --- | --- | --- | --- | --- | --- |
| **safestream-native** | **5.40 MB/s** | **0.754** | 0.412 | 0.437 | **25 MB** | **stated and tested** (Theorem 3, 1 GB test) |
| safestream-python | 1.87 MB/s | **0.754** | 0.412 | 0.437 | **9 MB** | stated and tested |
| presidio-regex | 0.13 MB/s | 0.422 | 0.292 | 0.546 | 67 MB | caller-managed |
| **safestream-native-ner** | 0.04 MB/s | 0.547 | **0.540** | 0.520 | 644 MB | stated (bounded window; model fixed cost) |
| presidio-sm | 0.02 MB/s | 0.364 | 0.455 | **0.659** | 237 MB | caller-managed (the harness feeds 20 k-char pieces) |
| presidio (lg) | 0.02 MB/s | 0.403 | 0.366 | 0.640 | 842 MB | caller-managed |

* **Dominated.** `presidio-regex` is worse than `safestream-native` on throughput,
  precision, character recall and memory (it wins only on entity recall, 0.546 vs
  0.437, which it buys with 0.42 precision). `presidio-sm` is worse than
  `safestream-native-ner` on throughput, precision and character recall.
* **On the frontier.** `safestream-native` (speed, precision, memory),
  `safestream-native-ner` (character recall), and `presidio-sm` (entity recall).
  Choosing between them is a trade-off, not a ranking.
* "Memory bound" means a *stated* bound with a test, not a measurement: SafeStream
  proves peak working memory `≤ chunk_size + overlap + L_max` independent of input
  (`docs/FORMAL_MODEL.md`, Theorem 3; `tests/test_memory.py`). Presidio documents no
  such bound; callers must chunk, and chunking can split entities.

## Closing the entity-recall gap (2026-10-02)

The table above predates the `mac_address`, `aws_account_id` and opt-in `date` detectors.
A span-level diff of the gold spans that `presidio-sm` fully redacts and
`safestream-*-ner` does not found three causes:

1. **Dates and times (3,404 spans).** Presidio maps spaCy's `DATE` and `TIME` labels to
   `DATE_TIME`. RedactionBench splits one date into about 5 gold spans, so every missed
   date costs 5 entities.
2. **MAC addresses (about 1,100 spans).** Presidio's `IP_ADDRESS` recognizer redacts them.
   SafeStream had no MAC detector.
3. **AWS account IDs** in ARNs and SQS URLs.

What remained after the fix is mostly Presidio's weak patterns firing on noise that happens
to overlap gold: `IN_PAN` on words like "Assessment", and `US_DRIVER_LICENSE` on any digit
run. Copying those patterns would trade precision for score.

Measured in one run on the full 200 documents. The tools ran in-process on Windows, so
there is no throughput or RSS column, and Presidio was fed 100 k-character pieces, which
shifts its numbers slightly from the 20 k-piece Linux table above. Each row uses the
pure-Python tier (byte-identical detections to native).

| Configuration | Entity recall | Char precision | Char recall | Mandatory span recall |
| --- | --- | --- | --- | --- |
| presidio-sm | 0.624 | 0.328 | 0.421 | 0.734 |
| safestream (no NER) | 0.500 | **0.760** | 0.430 | 0.693 |
| safestream + NER | 0.576 | 0.554 | 0.555 | 0.789 |
| **safestream + NER + `--dates`** | **0.647** | 0.492 | **0.577** | **0.805** |

With the date tier on, which matches the scope Presidio redacts by default, SafeStream
leads on every column. Its precision is still 1.5× Presidio's. Regenerate the official
table on Linux with the new `safestream-native-ner-dates` tool in `presidio_compare.py`.

## What the evidence does and does not support

* **Structured PII in noisy logs.** SafeStream catches every gold email, phone, card,
  SSN and IPv4 at 0.999 precision; Presidio's pattern recognizers reach 0.74 precision
  and 0.85 entity recall. **Caveat:** this corpus is generated by this repo
  (`generate_hard_dataset.py`) in the formats SafeStream targets, so it measures format
  coverage and false-positive resistance, not real-world recall.
* **Real documents.** On RedactionBench neither tool is close to complete (best
  character recall 0.54). Most SafeStream misses are names and free-text addresses
  that a pattern engine does not see.
* **Single run, shared machine.** Throughput ratios of 1.7–2× are within what scheduling
  noise on a shared container could move; the 15–147× pattern-tier ratios are not.

## Reproduce

```bash
pip install presidio-analyzer pyarrow
python -m spacy download en_core_web_sm && python -m spacy download en_core_web_lg
(cd native && maturin develop --release)        # for the safestream-native rows
python benchmarks/generate_hard_dataset.py --size-mb 1
python benchmarks/presidio_compare.py --out /tmp/out.md --json /tmp/out.json
```
